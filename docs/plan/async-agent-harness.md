# 에이전트 하네스 — Phase 3-4 비동기 발급 원정, 자율 주행 규칙

> **상태**: 확정 (2026-06-11). 격리 리뷰 2라운드 통과 — r1: Blocker 3·Caution 8·Note 4 전건 반영,
> r2: Blocker 0·Caution 4·Note 4(전건 반영) 판정 "조건부 가능" → 조건 해소 후 확정.
>
> **짝 문서**:
> - 원정 지도: `docs/plan/study-async-expedition-map.html` — *무엇을* 실험하는가
> - 리뷰어 정의: `.claude/agents/async-expedition-reviewer.md` — *누가, 무슨 기준으로* 검수하는가
> - 이 문서 — *어떤 루프로* 굴러가는가
>
> **용어 구분**: 이 문서의 "하네스"는 **에이전트 하네스**(워커-리뷰어 루프)다.
> k6·수렴 게이트·핀 assert 등 **실험 하네스**는 이 루프 안에서 만들어지는 산출물(CP1)이다.

## 1. 목적과 범위

- 원정 지도의 전 과정(스펙 → 실험 하네스 개조 → v6a→v6b→v6c → 잠정 회고·핸드오프)을 **사람 검수 없이** 자율 진행한다.
- 사람 검수의 대체물: **격리된 리뷰어 에이전트** + 이 문서의 루프·게이트 규칙.
- 적용 범위: **샌드박스 워크트리 내부 작업 전체** (셋업·teardown 포함). 본 레포로의 반영(머지·이식·본 실행)은 범위 밖 — 사용자가 결정한다.

## 2. 역할

| 역할 | 주체 | 하는 일 | 권한 경계 |
|---|---|---|---|
| 워커 | 메인 세션 (샌드박스 워크트리에서 구동) | 스펙·구현·측정·문서화, 로컬 커밋, 리뷰 요청 발행, 피드백 반영 | 샌드박스 내 쓰기 자유 (단, 메타 문서 제외 — §5-8). push 금지. 본 레포 수정 금지 |
| 리뷰어 | `async-expedition-reviewer` 서브에이전트 (격리 컨텍스트) | 체크포인트 산출물 검수, verdict 발행 | 읽기 전용. 산출물 수정·빌드·부하 실행 금지 |
| 사용자 | — | BLOCK 에스컬레이션 수신, 범위 변경·머지·본 실행 결정 | 최종 결정권 |

**격리 원칙**: 리뷰어는 워커의 대화 맥락을 받지 않는다. 받는 것은 리뷰어 입력 계약의 5항목
— 체크포인트 ID·라운드, 워크트리 루트, 본 레포 루트(메타 무결성 대조 전용), 산출물 경로 목록,
리뷰 로그 경로 — 뿐이다. 워커는 리뷰 요청에 자체 평가·설득·변명을 싣지 않는다
— 리뷰어가 산출물만 보고 판단하게 하는 것이 격리의 목적이다.

## 3. 체크포인트

리뷰는 체크포인트(CP) 단위로 받는다. 지도 §6 Expected Flow와 매핑:

| CP | 산출물 | 핵심 리뷰 관점 |
|---|---|---|
| CP-S | 샌드박스 셋업 기록 (`docs/reviews/cp-s-setup.md`) | push 차단 훅 존재+`--worktree` 스코프, `.claude/`·메타 문서 복사본=원본, 포트 상태 기록, TRANSFERABLE-TRAPS 점검 — **통과 전 CP0 진입 금지** |
| CP0 | 스펙 (`specs/`, `-draft`) | 설계 타당성(design-review 렌즈), Fork 결정 게이트, 핀 목록, 성공 시그니처, 비교 규율, **발급 상태 모델·조회 API 포함(T7)** |
| CP1 | 실험 하네스 개조 + **자가 검증 런 로그** | 수렴 게이트(T3)·카오스 스텝(T5/T6/T8)·핀 assert가 스펙대로 **실제 작동한 증거** (고의 불일치→abort 로그, 고의 미수렴→타임아웃 FAIL 분류 로그) |
| CP2 | v6a 구현 + 측정 + 기록 + 상태 조회 경로 | self-invocation(T1), executor 명시 핀(T2), 측정 수치 출처, 비교 규율 위반 |
| CP3 | v6b 구현 + 측정 + 기록 | 유실 재현·기록(T5), 통제변수 직전 버전 일치 |
| CP4 | v6c 구현 + 측정 + 기록 | 재전달·중복 흡수(T6), 유니크 제약, PEL 회수 |
| CP5 | **잠정 회고**(지도 채점 — 출처 라벨 강제) + **핸드오프 묶음** + teardown | 채점 출처 규율, 빗나간 예보 은폐 없음, T7 탈락 통보 지연·T9 역전 기록, 핸드오프 완비, 포트 free |

**CP5 채점 출처 규율**: 자율 주행 시점의 수치는 전부 샌드박스 리허설 수치다. 지도의
`실측 후 기입` 빈칸은 **"샌드박스 리허설 실측" 출처 라벨을 붙여 잠정 채점**하며,
본 실행(main repo) 후의 최종 채점은 별도로 남는다 — 지도 말미의 "실측 표기는 동결본만" 규율을
리허설 수치로 오염시키지 않기 위함이다.

**핸드오프 묶음** (지도 §6 Step 3): 검증된 실험 하네스 + 개정 스펙 + 전이 트랩 목록 + 핀 목록
+ teardown 완료(샌드박스 인프라 내림, 포트 3306·6379 free 확인). 이것이 CP5 산출물의 일부다.

## 4. 루프

```
워커: CP 산출물 완성
  → 로컬 커밋 (메시지에 "cp{N}-r{R}" 포함 — 리뷰 대상 스냅샷 고정)
  → 리뷰어 호출 (Agent tool, subagent_type: async-expedition-reviewer)
  → verdict 수신 즉시 리뷰 로그 기록 (docs/reviews/cp{N}-r{R}.md, verdict 원문 — PASS/REVISE/BLOCK 불문)
  → 분기:
       PASS          → 로그에 반영 내역 추가 → 다음 CP
       REVISE        → findings 반영 → 커밋 → 재리뷰 (라운드 +1)
       BLOCK         → 즉시 중단 → §6 에스컬레이션
       INVALID-INPUT → 호출 입력 보완 후 재호출 (라운드 미소모). 2연속 INVALID-INPUT이면 BLOCK으로 간주
```

- **라운드 상한**: CP당 3라운드 (INVALID-INPUT 재호출은 라운드를 소모하지 않는다).
  r3까지 REVISE면 BLOCK으로 전환한다.
- **핑퐁 판정의 단일 소스는 리뷰어 산식이다**: 동일 Blocker가 실질적 진전 없이 재제출되면
  리뷰어가 BLOCK을 낸다 (수정 시도의 부분 진전이 있으면 r3까지 허용). 워커는 자체 핑퐁 판단을 하지 않는다.
- **verdict 파싱 실패·자기모순** (예: `VERDICT: PASS`인데 `blocker=1`): 1회 재호출(라운드 미소모).
  재발하면 BLOCK으로 간주하고 에스컬레이션 보고에 원문을 첨부한다.
- **리뷰어 행동 위반**: 리뷰어가 파일을 수정했거나 빌드·부하를 실행한 흔적이 있으면
  해당 verdict는 무효 — 1회 재호출, 재발 시 BLOCK.
- **Caution 처리**: Blocker 0이면 Caution이 있어도 PASS다. 워커는 Caution을 해당 CP 문서
  (스펙 명기 또는 백로그)에 반영하고 커밋한 뒤 다음 CP로 간다 — 재리뷰는 불요.
  **반영 여부는 다음 CP 리뷰어가 직전 CP 리뷰 로그를 받아 확인**하며, 미반영은 새 Blocker로 지적된다.
  CP5의 Caution은 다음 CP가 없으므로 핸드오프 묶음·최종 보고에 미반영 목록으로 명시 이관한다.
- **로그 파일 규칙**: INVALID-INPUT·형식 불량 verdict도 같은 라운드 로그 파일(`cp{N}-r{R}.md`)에
  **append**한다. 한 파일에 verdict가 여럿이면 최하단 verdict가 유효하다.

## 5. 안전 규칙 (워커 의무)

1. **push 절대 금지.** 샌드박스 생성 직후 push 차단 훅을 설치하되, 반드시
   `git config extensions.worktreeConfig` + `--worktree` 스코프로 설정한다.
   `--local`은 본체 레포까지 오염시킨다 (phase 3-3 실측 교훈).
2. **로컬 커밋은 자유.** 최소 단위: 리뷰 라운드마다 1커밋 (리뷰 대상 고정용).
   본 레포 커밋은 기존 규칙 유지 — 사용자 확인 후에만.
3. **포트 가드.** 샌드박스 인프라(3306·6379)와 본 레포 인프라를 동시에 띄우지 않는다.
   기동 전 포트 점유를 확인하고, 점유 중이면 기동하지 않고 §6으로 에스컬레이션한다.
   **본 레포 인프라(컨테이너·프로세스)를 내리거나 조작하는 것은 금지** — 사용자 환경이다.
4. **`docker compose down -v` 금지.** 스키마·시드가 증발한다. 필요해 보이면 BLOCK 사유다.
   카오스 스텝(T5/T6/T8)의 kill 대상은 앱·워커 **프로세스**이지 인프라 컨테이너가 아니다.
5. **compose env는 `docker/.env`.** 루트 `.env`는 compose가 읽지 않는다 (phase 3-3 실측 교훈).
6. **`.claude/` 복사.** `.claude/`는 gitignore라 워크트리 체크아웃에 딸려오지 않는다.
   샌드박스 셋업 시 본 레포의 `.claude/agents/`·`.claude/commands/`를 워크트리로 복사한다
   (리뷰어 정의·기존 커맨드가 콜드 세션에서 보이게).
7. **TRANSFERABLE-TRAPS 우선.** 새 워크트리·콜드 세션에서 phase 3-3 발견 클래스 A
   (gradle wrapper jar, 스키마 볼륨 등 버전관리 밖 산출물 의존)가 재발할 수 있다 — 셋업 첫 화면에 둔다.
8. **메타 문서 수정 금지.** 이 문서, `.claude/agents/async-expedition-reviewer.md`,
   `.claude/commands/design-review.md`는 자율 주행 중 워커·리뷰어 누구도 수정하지 않는다.
   수정이 필요해 보이면 그 자체가 BLOCK 사유다. 리뷰어는 매 라운드 워크트리 사본이
   본 레포 원본과 diff 0인지 대조한다 — 불일치는 즉시 BLOCK.
   **원정 지도도 보호 대상이다**: `docs/plan/study-async-expedition-map.html`은 CP5 전까지 diff 0,
   CP5에서는 `실측 후 기입` 슬롯과 예측 카드 채점 기입분만 허용 — 그 외 diff(특히 §5 규율 문구 변경)는 BLOCK.
   이 대조는 우발적·드리프트성 변조를 검출하는 장치다. 표적 변조·로그 위조까지 막지는 못한다
   (위협 모델 밖 — 워커의 기본 정직성은 신뢰 가정이며, 사용자는 BLOCK 수신 시 메타 diff 스팟체크를 권장).

## 6. 에스컬레이션 (BLOCK)

다음 중 하나면 **즉시 중단하고 사용자에게 보고**한다:

1. CP 리뷰 3라운드 소진
2. 리뷰어가 핑퐁(동일 Blocker 실질 미해소) 판정
3. 지도 범위 밖 결정이 필요할 때 — Fork A로의 전환, Kafka 도입, 스키마 파괴적 변경 등
4. 핀 assert 불일치가 원인 불명으로 재현되어 측정 자체가 무효일 때
5. 데이터·환경 파괴적 작업이 필요해 보일 때 (`down -v` 포함)
6. 리뷰어가 BLOCK verdict를 낼 때 (2연속 INVALID-INPUT, verdict 형식 불량 재발 포함)
7. 포트 3306·6379 점유로 샌드박스 인프라를 기동할 수 없을 때 (본 레포 인프라 조작 금지)
8. 메타 문서(§5-8) 수정이 필요해 보일 때

보고 형식: 현재 CP·라운드 / 막힌 지점 / 시도한 것 / 선택지 제안 (권장안 포함).
보고 후에는 사용자 입력 없이 재개하지 않는다.

## 7. 기록과 경로 규칙

- **리뷰 로그**: 샌드박스 `docs/reviews/cp{N}-r{R}.md` — 리뷰어 verdict 원문 + 워커의 반영 내역.
  모든 라운드(PASS/REVISE/BLOCK)에 의무다 — 다음 라운드·다음 CP 리뷰어의 입력이 된다.
- **경로 규칙**: 산출물·기준 문서 경로는 전부 **워크트리 루트 기준**이다.
  유일한 예외는 메타 문서 무결성 대조(§5-8)로, 이때만 본 레포 원본 경로를 쓴다.
- 리뷰 로그는 CP5 잠정 회고의 1급 재료다. 실험 회고와 별도로 **에이전트 하네스 자체의 회고**
  (라운드 수 분포, 핑퐁 발생 여부, 리뷰어가 놓친 것)를 한 절로 남긴다.

## 8. 이 하네스 자체의 검증

- 이 문서와 리뷰어 정의는 격리 리뷰(design-review 렌즈)를 거쳐 확정한다.
  r1 리뷰(2026-06-11): Blocker 3·Caution 8·Note 4 → 전건 반영. r2 재검수 통과 시 확정.
- 확정 시 헤더의 draft 표기만 제거하며 **파일명은 유지**한다 (`async-agent-harness.md`) —
  리뷰어 정의가 이 경로를 참조하므로 rename은 리뷰어 정의 동시 수정 없이는 금지.
- 확정 전에는 샌드박스를 생성하지 않는다. 확정 시점부터 루프 규칙은 워커·리뷰어 모두에게 구속력을 가진다.
