# Pull Request Convention

AI Agent(Claude Code)는 PR을 생성할 때 작업의 성격(Type)에 따라 아래 두 가지 템플릿 중 하나를 선택하여 작성해야 한다.

## 1. 공통 규칙
- **제목(Title):** 반드시 **영어**로 작성한다.
    - 형식: `type: Phase N - {Concise English Description}`
    - 예시: `feat: Phase 2 - Domain Entities and Database Schema`
- **본문(Body):** 반드시 **한글**로 작성한다.
- **워터마크 금지(No Watermark):** 본문 하단에 "Generated by Claude Code", "AI 작성됨" 등의 서명이나 문구를 **절대 포함하지 않는다.** 사람이 직접 작성한 것처럼 깔끔하게 마무라한다.

---

## 2. 템플릿 선택 가이드

### Type A: 일반 기능 및 설정 (Feature & Setup)
- **대상:** Phase 1 (초기화), Phase 2 (도메인), Phase 4 (모니터링), Phase 5 (문서)
- **목적:** 구현된 기능과 설정 방법을 명확히 전달함.

#### [Type A 템플릿]
```markdown
## 개요
{작업의 목적을 1-2문장으로 요약}

## 작업 상세 내용
{구현한 기능, 설정, 구조 변경 사항을 카테고리별로 정리}
- **{카테고리}:** {상세 내용}
- **{카테고리}:** {상세 내용}

## 변경된 스펙 (Optional)
- {기존 계획에서 변경된 기술 스택이나 설계가 있다면 명시}

## 테스트 방법
{리뷰어가 코드를 실행하고 검증하는 방법}
1. **실행 명령어:** `{command}`
2. **확인 사항:** {기대 결과}
```

### Type B: 성능 최적화 및 실험 (Optimization)
- **대상:** Phase 3-1 ~ 3-4 (인덱스, N+1, 랭킹, 동시성)
- **목적:** Before/After 성능 비교와 문제 해결 과정을 수치로 증명함.

#### [Type B 템플릿]
```markdown
## 개요
{어떤 성능 문제를 해결했는지 1-2문장으로 요약}

## 시나리오 구현 (v1 ~ v4)
{단계별 구현 내용을 요약}
- **v1 (Before):** {최적화 전 상태 설명}
- **v2~v3 (Step):** {중간 최적화 단계}
- **v4 (After):** {최종 최적화 기술 적용}

## 성능 분석 (Performance Analysis)
**핵심 지표 비교**
| 단계 | 방식 | 응답시간(Avg) | 처리량(TPS) | 쿼리 수 |
|---|---|---|---|---|
| v1 | {방식명} | {00}ms | {00} | {00} |
| v4 | {방식명} | {00}ms | {00} | {00} |

**결과 요약**
- {v1 대비 v4에서 성능이 몇 % 향상되었는지, 어떤 트레이드오프가 있었는지 기술}

## 테스트 방법
{부하 테스트 실행 방법}
1. **스크립트 실행:** `k6 run test/load/{script}.js`
2. **검증:** {확인해야 할 로그나 데이터 정합성}
```

## 3. 실행 명령어 (Execution Command)
- PR 본문 작성이 완료되면, GitHub CLI를 사용하여 아래 명령어로 PR을 생성한다.
gh pr create --title "{Title}" --body "{Body Content}"
