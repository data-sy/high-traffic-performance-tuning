# Phase 3-9 — 직렬 임계 구간 점유: in-lock 왕복 단축의 throughput 번역 (반증 가능 측정)

> 스펙: `specs/phase3/phase3-9-critical-section-occupancy.md` · 측정 기판: **base 프로파일**(utf8mb4 · redis 6379 ·
> phase3-8 latin1 아님) + 측정 전용 `occupancy` 프로파일(부팅 assert) · 부하 런은 `quietsql` 오버레이(SQL DEBUG OFF).
> 컨테이너 프로젝트 `docker`(mysql 3306 · redis 6379). 500 VU 단일 핫키(coupon_id=1) 폐루프, 매 런 canonical 리셋.

## 헤드라인 판정 — **H_floor 지지 (헤드라인 입증)**

단일 핫 로우 비관락 워크로드에서, 임계 구간 비용은 in-lock DB 왕복 *수*가 아니라 **commit floor**(X-락을 COMMIT까지
쥐는 insert-flush/fsync)가 지배한다. 왕복을 **4→3→2로 깎는 것은 구조적으로 실재**(프로브로 확정)하나 **throughput으로는
약하게만 번역**된다: 관측 `r = tput(R4)/tput(R0) = 1.20`, H_왕복 예측(`r≈2.0`)과 거리가 멀고 반증 문턱 `1.5`에 못 미친다.
R1 풀 스윕이 pool 10→20→30에서 **평평**(ceiling=점유시간, not 풀)해 이를 독립 보강한다.

- **ε 재확정(Step 3):** R0·R4 각 **n=6** 결합 CV 상한 **`ε_hi = 26.12%` < 0.5** → 사전 등록 판정 **유효**(밴드 비겹침).
- **정직 단서(M6):** `r=1.20`은 지지밴드 `[0.739, 1.261]`의 **상단 가장자리**다. 점추정 밴드(`ε_point=12.5%` → `[0.875,1.125]`)로
  읽으면 `1.125 < 1.20 < 1.5`라 **미결(부분 지배)**로 떨어진다. 게이트 집행값은 `ε_hi`(스펙 규칙 1·2)라 공식 판정은 **지지**지만,
  **점 신호는 "제로 번역"이 아니라 ~20% 부분 번역**이다 — commit floor가 지배하되 왕복 감축을 *완전히* 가리진 않는다.
  **핵심(왕복수 비례 아님, `r≉2.0`)은 견고**하게 입증됐고, "거의 번역 안 됨"은 "부분(≈20%) 번역"으로 정직 수정한다.

## 1. 구조 축 — 프로브 카운트 (M1, 동시성 0 단일요청 + 정적 카운트, 결정론)

| 칸 | in-lock 왕복 수(기대) | 관측 | flush 순서(관측==기대) | 게이트 |
|---|---|---|---|---|
| **R0** | 4 | **4** | FORUPDATE, ISSUESEL, INSERT, UPDCOUPON | ✅ PASS |
| **R1** | 4 | =R0 | 코드 동일(R0 서비스), 풀만 스윕 | =R0 |
| **R2** | 4 | **4** | FORUPDATE, ISSUESEL, INSERT, UPDCOUPON | ✅ PASS (existsBy 앞 UPDATE 없음) |
| **R3** | 3 | **3** | UPDCOUPON(tryConsume), ISSUESEL, INSERT | ✅ PASS |
| **R4** | 2 | **2** | UPDCOUPON(tryConsume), INSERT | ✅ PASS |

- UPDCOUPON = `update coupon`: R0/R2는 커밋 dirty-flush, R3/R4는 `tryConsume` 조건부 UPDATE(엔티티 미적재 → 커밋 UPDATE 소멸).
- **3개 배선 게이트 전부 충족:** (i) 칸별 프로브 카운트 표 일치, (ii) 전 칸 flush 순서 게이트(R2 조기 auto-flush 없음 실측),
  (iii) `PreRegisteredAdjudicationGate`(§3) 배선·발화.
- 증거 SQL: `probe-counts.txt`. 예) R4 `update coupon c1_0 set issued=(c1_0.issued+1) where c1_0.id=? and c1_0.issued<c1_0.total_qty` → `insert into coupon_issue ...` (2문).

## 3. 사전 등록 판정 — `PreRegisteredAdjudicationGate` (채점 스텝, 부팅 빈 아님)

```
R0: n=6 mean=307.8/s CV=11.51% CV_hi=24.04%
R4: n=6 mean=370.4/s CV=4.88%  CV_hi=10.20%
결합 ε 점추정 = 12.50%   ε_hi(χ² σ-bound 신뢰상한) = 26.12%
ρ*=2.0  ε-gate=(ρ*−1)/2=0.5  반증문턱=1+(ρ*−1)/2=1.5
관측 r = tput(R4)/tput(R0) = 1.2034
⇒ 판정: H_floor 지지 (0.739 ≤ r ≤ 1.261, commit floor 지배)
```

- **밴드 비겹침 자격(규칙 2):** `ε_hi=26.12% < 0.5` → 지지/미결/반증 밴드 비겹침 성립 → 판정 유효(보류 아님).
  파일럿 잠정치 `ε_hi=21.9%`(R0 단독)를 R4 빌드 후 **결합 CV**로 재확정: 26.12%. ~√2×여도 <0.5라 결론 견고(스펙 예측대로).
- **분류(규칙 4):** `1−ε_hi ≤ r ≤ 1+ε_hi` → **H_floor 지지**. `r=1.20`은 H_왕복 예측 2.0과 거리 멀고 반증 문턱 1.5 미달.
- **게이트는 `ε_hi`로 집행**(점추정 아님, 규칙 1) → 소표본 과소추정이 조용히 통과하지 못함. 정본 verdict JSON:
  `adjudication-verdict.json`.

### 거울 확인 R3 (정성 보강만, 정량 반증권 없음 — 규칙 5)
- `ε_hi=26.12% ≥ 16.5%(=（ρ_R3−1)/2)` → **R3 정량 판정 보류**. R0·R3·R4 3점 **정성 추세**로만 읽는다.
- 추세: **R0 307.8 < R3 344.7 < R4 370.4/s** — 왕복 4→3→2에 따라 **단조 상승**. 이는 H_왕복을 *정성적으로* 약하게 보강하나,
  기울기가 기준비 선(ρ*=2.0)에 크게 못 미쳐(총 상승 ~20%) **H_floor 지배와 정합**. R4(유일 ε-가드 정량점)가 정본이며 R3
  정성 추세와 어긋나지 않는다.

## 4. 진단 축 — R1 풀 스윕 (음성 대조군, r1 endpoint = R0 코드)

| pool | throughput | 503 | 판정 |
|---|---|---|---|
| 10 | 329.8/s (R0 코드 mean 307.8) | 0 | — |
| 20 | 325.7/s [344.1, 307.3] | 0 | — |
| 30 | 332.4/s [337.2, 327.5] | 0 | — |

- **throughput이 풀에 평평**(~308–332/s, 노이즈밴드 내) → **천장 = 점유시간(H_floor 측), not 풀.** 전제 **반증 안 됨**.
- **503 관측:** pool 30에서도 **503=0**(큐깊이×임계구간 fsync 꼬리가 기본 `innodb_lock_wait_timeout=50s` 미초과). 스펙이
  허용한 R1 503>0 시나리오는 이 스케일에선 미발화(관측치로 기록, abort 아님).
- pending(200−pool)은 별도 샘플링 안 함 — throughput-평평이 R1 1차 시그니처(스펙: pending은 강등 보조).

## 5. 측정 유효성·자가검증 (M2·M5)

- **부팅 assert(M2·M5a):** `CriticalSectionPinsBootAssert`(@Profile("occupancy"))가 실제 Hikari pool·Tomcat threads 대조.
  - 정상: pool=10/20/30 각각 `기대==실제`, threads=200 일치 → 기동.
  - **고의 불일치 자가검증(M5a):** `OCCUPANCY_EXPECT_POOL=999`(실제 10) → `IllegalStateException`으로 **기동 중단**(EXIT=1)
    확인. 부팅 핀이 substrate 무결성을 집행함을 실증.
- **채점 게이트 자가검증(M5c):** ε 게이트가 `ε_hi`로 집행됨을 게이트 스크립트로 검증(파일럿 R0 CV 9.24%·n=5 → `ε_hi=21.92%`
  재현, χ² σ-bound 건전성). ε_hi≥0.5 주입 시 하드 거부(판정 보류) 경로 코드 존재(`adjudication-gate.py`).
- **통제변수 런타임 assert:** 매 런 `innodb_lock_wait_timeout=50`·isolation=REPEATABLE-READ·redis PONG 실측 대조 통과.

## 6. 결론

1. **구조적 단축은 실재한다** — 프로브가 R0=4·R3=3·R4=2 왕복을 결정론으로 확정(3개 배선 게이트 통과).
2. **그 단축의 throughput 번역은 약하다** — `r=1.20`(≪2.0), `ε_hi=26.12%<0.5`로 판정 유효, **H_floor 지지**. commit floor가
   임계 구간 비용을 지배한다는 헤드라인이 **부하 런으로 반증 가능하게 입증**됐다.
3. **정직 후퇴(M6):** 점 신호는 "거의 0 번역"이 아니라 **~20% 부분 번역**(지지밴드 상단). "왕복 수에 *비례*(2×)"는 명확히
   반증됐으나, 왕복 감축이 소폭 실익을 주는 것도 사실이다. 과대 단정("완전 무번역")과 과소 단정("왕복이 천장") 사이의
   **혼합**이 가장 정직한 서술이며, 게이트 규칙상 공식 라벨은 "지지".
4. **R1 독립 보강** — 풀을 늘려도 평평 → 천장은 의자(풀)가 아니라 점유시간. **채택 결정 아님**(스펙 규율): "무엇을 줄이면
   무엇이 commit floor에 가려지는가"를 측정으로 가른 것이다.
